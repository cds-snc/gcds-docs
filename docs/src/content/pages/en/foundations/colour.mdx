# Colour

We use colour to create hierarchy, communicate meaning, and support consistent experiences across components and products.

## Colour palette

The palette includes 6 colour scales, each progressing from lighter to darker shades. Together, they provide the range of colours used throughout GC Design System.

<ColourPalette scales="grayscale red yellow green blue purple" />

Each colour scale has a general role in the system. These roles guide how we use colour, but they do not define every use.

<gcds-grid tag="ul" columns="1fr" columns-tablet="1fr 1fr">
  <li class="list-none">

  </li>

  </li>
  <li class="list-none">
    <strong>Red</strong><br/>Critical information, errors, destructive actions.
  </li>
  <li class="list-none">

  <li class="list-none">
    <strong>Yellow</strong><br/>Warnings and alerts.

  <li class="list-none">
    <strong>Purple</strong><br/>Specialty states and specific highlights.
  </li>
</gcds-grid>

### Additional colours

In addition to the 6 scales, the palette includes 4 individual colours.

<ColourPalette singles="white blue-vivid blue-muted black" />

Blue-vivid provides visual prominence for interactive elements. Blue-muted supports familiarity with Canada.ca and Government of Canada products.

All colours in the palette are defined as <gcds-link href={`${links.en.designTokens}#base-tokens`}>base tokens</gcds-link>. These tokens have no assigned meaning or purpose and are used to create semantic colour tokens.

## Semantic colours

Semantic colours give colour a specific meaning or purpose in the interface. They help form the brand identity for the Government of Canada.

Semantic colours are represented by <gcds-link href={`${links.en.designTokens}#global-tokens`}>global tokens</gcds-link>. These tokens connect colours from the palette to specific uses, such as text, backgrounds, borders and interactive states. This lets us apply the same colour decisions consistently.

<gcds-link class="d-block mb-300" href="#global-colour-tokens">Browse global colour tokens</gcds-link>

## Using colours

### Select colour tokens purposefully

Choose global colour tokens based on their meaning and how well they match your needs. This helps maintaining the intended meaning of colours across interfaces.

### Check colour contrast

When combining GC Design System colours in your own styles, check that the combinations meet standards for accessible colour contrast using accessibility contrast tools, like <gcds-link external href={links.en.webaim} target="_blank">WebAIM Contrast Checker</gcds-link>.

### Choose how to apply colour

When you need to apply colour outside a component:

- Use a CSS Shortcuts class when one is available for the style you need, such as <gcds-link href={links.en.textColourShortcut}>text colour</gcds-link>, <gcds-link href={links.en.linkColourShortcut}>link colour</gcds-link>, or <gcds-link href={links.en.backgroundColourShortcut}>background colour</gcds-link>.
- Use a global colour token when CSS Shortcuts do not meet your needs.
- Use a base token only when there’s no appropriate global colour token.
