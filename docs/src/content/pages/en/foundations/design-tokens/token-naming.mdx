# Design token naming

Understanding what a token’s name means will help you choose and apply the right one.

## Naming convention

Token names follow a structure that describes what each token represents.

Token names do not always use every segment, only those needed to describe the token.

### Base token naming

- The **category** describes what the style is about.
- The **hue** specifies the colour.
- The **scale** identifies a value in a series of shades, with numbers increasing at regular intervals.

### Global token naming

- The **category** describes what the style is about. The “color” category is omitted in global colour token names.
- The **role** specifies the subtype or level of emphasis, like primary or secondary.
- The **state** specifies the global interaction or data state, like danger, disabled, or focus.
- The **scale** specifies a value within a set of proportionally increasing sizes or weights.
- The **property** is what’s being styled, like text or background. It can use more than one word, like border-width.

<img

In --gcds-focus-text, --gcds is the prefix, focus the state, and text the property."
/>

### Component token naming

- The **component** identifies the component the style applies to.
- The **role** specifies the subtype or level of emphasis, like primary or secondary.
- The **state** cites the interaction or data state, like default, hover, focus, etc.
- The **property** is what’s being styled, like text, background, or border. It can use more than one word, like border-width.
