# How it works

Before you install anything, it helps to know what you’re installing. This section covers the questions
developers ask most: what web components are, what shadow DOM does, how much you can customize, and
whether it’s really accessible. It also covers the parts that aren’t perfect yet.

## GCDS components are just HTML tags

GCDS is built with <strong>web components</strong>, a browser standard, not a framework. A web component is
a custom HTML tag that the browser knows how to draw. Once the GCDS script is on the page, you write one tag and get a working, accessible, on-brand button:

The code under the example changes to match the framework you chose. Use the menu above the example to
compare frameworks.

Because the browser itself understands these tags, the same component works in plain HTML, React, Vue,
Angular, a CMS template or a server-rendered Java or .NET app. The framework packages
(<code>@gcds-core/components-react</code> and so on) are thin wrappers that make the tags feel native in each
framework: typed props, <code>v-model</code>, <code>ngModel</code>, and so on.

## What shadow DOM is, and why GCDS uses it

Inside each GCDS component is its own small piece of HTML and CSS, called a <strong>shadow root</strong>.
Styles inside it don’t leak out, and, more importantly, styles from your page don’t leak in.
